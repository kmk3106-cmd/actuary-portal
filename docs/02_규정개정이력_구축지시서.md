# 02. 규정 개정이력 관리 구축 지시서

계리결산팀 운영관리포탈에 **규정 개정이력 관리 페이지**를 만든다.

작성 2026-10-18 · 대상 `portal.kkuks.com` · 요청자 계리결산팀장

---

## 0. 한 장 요약

| 항목 | 내용 |
|---|---|
| 만들 것 | 새 페이지 `reg-history.html` + 새 테이블 2개 + 수집 작업 1개 |
| 쓸 것 | 기존 `kb-sop.html` 의 문서 저장 구조 · `kbc_regulation` 카테고리 |
| 핵심 | 개정 시기별 목록 → 상세 열람 → **외부 공고를 실제로 가져와 적재** |
| 1차 목표 | 수동 등록으로 목록·상세가 돌아가는 상태 |
| 2차 목표 | 국가법령정보 공개 API로 확정 개정이 자동으로 들어오는 상태 |

## 1. 배경

보험업감독규정·시행세칙은 1년에도 여러 차례 바뀐다. 지금은 개정이 생길 때마다 담당자가 개별로 확인하고, 분석 결과는 메일이나 개인 폴더에 흩어진다. 그래서 이런 일이 생긴다.

- 어떤 개정이 **언제 시행되는지** 한눈에 보이지 않는다
- 반년 전 개정의 **분석 자료를 다시 찾기 어렵다**
- 사전예고를 **놓치면** 의견제출 기회가 사라진다
- 개정에 따른 **조치가 끝났는지** 추적되지 않는다

이 네 가지를 해결한다.

## 3. 만들 것

### 3-1. 화면

```
reg-history.html
├ A. 타임라인      연도·분기별 개정 목록
├ B. 상세 패널     선택한 개정 1건
├ C. 수집함        자동 수집된 후보 · 등록 전
└ D. 등록·수정 폼  수동 입력
```

사이드바에는 **업무** 그룹 아래 “규정 개정이력”으로 넣는다. `buildSidebar` 의 기존 메뉴 정의에 추가한다.

### 3-2. 테이블

새로 만든다.

```
reg_items   개정 건 본체
reg_inbox   자동 수집 후보
```

수집원 정의는 1차에서는 **서버 설정 파일**로 둔다. 운영하면서 자주 바뀌면 그때 `reg_sources` 테이블로 뺀다.

### 4-2. reg_inbox

자동 수집이 주워 온 후보다. 사람이 보고 등록하거나 버린다.

  "source": "law.go.kr",              // 수집원 키

### 4-3. 저장 위치

기존 JSON DB 규칙을 따른다. 첨부 파일은 테이블에 넣지 말고 디스크에 두고 경로만 저장한다.

```
data/reg_items.json
data/reg_inbox.json
files/reg__{id}/…           원문 첨부
```

## 5. 화면 명세

### 5-1. A. 타임라인

```
┌ 필터 ─────────────────────────────────────────┐
│ 규정구분 ▾   상태 ▾   영향도 ▾   담당 ▾   [검색…] │
└──────────────────────────────────────────────┘

2026년
  4분기  ● 시행   2026.10.01  시행세칙  계리적 가정 산출기준 개정     대   리포트
         ○ 공포   2026.10.15  감독규정  …                          중
  3분기  ● 예고   2026.06.19  시행세칙  …                          대
2025년
  …
```

- **시행일 역순**이 기본 정렬 · 시행일이 없으면 예고일로 정렬
- 연도 → 분기 2단 그룹
- 상태는 색 배지로 구분한다
- 리포트가 연결된 건은 표시한다
- 행을 클릭하면 B 상세가 열린다

**세로축은 시간이다.** 분기 머리에 그 분기의 건수를 적는다.

### 5-2. B. 상세

```
제목
규정명 · 조문 · 소관

[일정]      예고 2026.06.19 → 의견제출 2026.07.29 → 시행 2026.10.01
[변경]      신설 10 · 변경 6 · 이동 1
[영향]      대 · 해약률 가정 · 위험률 가정
[출처]      사전예고 공고 ↗  ·  신구조문 대비표 ↓
[리포트]    신구조문 대비 리포트 보기 ↗
[조치]      1 납입기간 중 해약률 모형 대조   담당 —   상태 대기
            2 …
[이력]      2026-10-18 김민국 등록
```

- **리포트 보기**는 `kb-sop.html` 의 해당 문서로 이동하거나, 같은 `iframe srcdoc` 을 여기서 바로 펼친다. 둘 중 하나를 고르되 **새 렌더러를 만들지 않는다.**
- 조치 항목은 상태를 바로 바꿀 수 있게 한다.

### 5-3. C. 수집함

```
[수집 실행]   마지막 수집 2026-10-18 06:00

□ 2026-10-15  law.go.kr    보험업감독업무시행세칙 일부개정   [등록] [무시]
□ 2026-10-02  fss          보험업감독규정 시행세칙 개정 예고  [등록] [무시]
```

- **등록**을 누르면 D 폼이 수집값으로 채워진 채 열린다
- **무시**는 `state: "무시"` 로 바꾼다 · 지우지 않는다
- 중복은 `hash` 로 거른다

### 5-4. D. 등록·수정 폼

4-1의 필드를 입력받는다. 필수는 네 가지다.

```
필수   title · reg_type · reg_name · status
권장   date_effective · summary
```

리포트 HTML은 **파일 업로드**로 받아 `wrapForPortal()` 을 거쳐 `kb_documents` 에 저장하고, 돌아온 id를 `report_doc_id` 에 넣는다. 감싸는 코드는 `docs/01_리포트_스타일가이드.md` 5-2에 있다.

## 6. 수집 설계

**핵심 요구사항이다.** 실제로 검색해서 진짜 개정된 규정이 들어와야 한다.

### 6-1. 세 갈래

| 경로 | 무엇을 가져오나 | 신뢰도 | 난이도 |
|---|---|---|---|
| A. 국가법령정보 공개 API | 공포된 개정 · 조문 본문 · 별표 파일 | 높음 | 낮음 |
| B. 금감원·금융위 공고 | 사전예고 · 입법예고 · 보도자료 | 중간 | 높음 |
| C. 수동 등록 | 사내 공문 · 질의회신 | — | — |

**A를 먼저 붙인다.** 확정된 개정은 A로 다 들어오고, 신청만 하면 안정적으로 쓸 수 있다.

### 6-2. A. 국가법령정보 공개 API

확인된 사실만 적는다.

```
신청    https://open.law.go.kr  →  OPEN API 신청 · API인증키관리
문의    02-2109-6446

목록    https://www.law.go.kr/DRF/lawSearch.do?OC={인증키}&target={대상}&query={검색어}
본문    https://www.law.go.kr/DRF/lawService.do   ← 목록 결과의 일련번호 또는 상세링크 사용
```

| target | 대상 |
|---|---|
| `admrul` | **행정규칙** — 감독규정 · 시행세칙이 여기 속한다 |
| `eflaw` | 현행법령 · 시행일 기준 |

제공 기능 중 본 과제에 쓸 것

```
행정규칙 목록 조회
행정규칙 본문 조회
행정규칙 신구법 비교      ← 신구조문 대비 자동 추출에 쓸 수 있다
법령 연혁
```

**별표 파일 받기** — 본문 조회 응답의 `별표서식파일링크` 또는 `별표서식PDF파일링크` 값을 `https://www.law.go.kr` 뒤에 붙여 호출한다.

```
https://www.law.go.kr/LSW/flDownload.do?flSeq={번호}
```

> 별표22·별표35가 바로 이 별표다. 개정 때마다 이 파일을 받아 `files/reg__{id}/` 에 저장한다.

**확인이 필요한 것** — `type`(JSON/XML) · `display` · `page` 같은 공통 파라미터의 정확한 이름과 기본값은 신청 후 활용가이드에서 확인한다.

```
활용가이드   https://open.law.go.kr/LSO/openApi/guideList.do
샘플코드     https://open.law.go.kr/LSO/lab/sampleCode.do
```

**감시 대상**

```
보험업감독규정
보험업감독업무시행세칙
보험업법 시행령        ← 필요 시
```

### 6-3. B. 금감원·금융위 공고

사전예고와 입법예고는 법령정보센터에 올라오지 않는다. 확정 전이기 때문이다. 그래서 공고 목록을 직접 봐야 한다.

**수집원 후보**

```
금융감독원      보도자료 · 사전예고
금융위원회      보도자료 · 입법예고
법제처 통합입법예고센터
```

**반드시 지킬 것**

```
□ 각 사이트의 robots.txt 와 이용약관을 먼저 확인한다
□ 요청 간격을 둔다 — 최소 2초
□ User-Agent 에 연락 가능한 식별자를 넣는다
□ 하루 1회로 제한한다
□ 목록 페이지만 긁고 본문은 링크만 저장한다
```

**선택자를 코드에 박지 않는다.** 설정 파일로 뺀다. 사이트 개편 때 코드를 안 고치려는 것이다.

```jsonc
// config/reg_sources.json
{
  "fss_notice": {
    "label": "금융감독원 사전예고",
    "list_url": "https://…",
    "row": "…",            // 행 선택자
    "title": "…",
    "link": "…",
    "date": "…",
    "date_format": "YYYY-MM-DD",
    "keywords": ["보험업감독", "시행세칙", "계리"],
    "enabled": true
  }
}
```

**수집이 실패하면 조용히 넘어가지 않는다.** 로그를 남기고 수집함 상단에 “fss_notice 수집 실패 · 2026-10-18” 을 띄운다. 선택자가 깨진 것을 사람이 알아야 한다.

### 6-4. 실행

```js
// Node · 하루 1회
// 서버에서 돌린다 — 브라우저에서 하면 CORS 로 막힌다
cron: "0 6 * * *"        // 매일 06:00
```

흐름

```
1  수집원을 돌며 목록을 받는다
2  키워드로 거른다
3  hash 로 중복을 뗀다
4  reg_inbox 에 state:"신규" 로 넣는다
5  신규가 있으면 수집함 배지에 건수를 띄운다
```

**자동으로 reg_items 에 넣지 않는다.** 사람이 수집함에서 확인하고 등록한다. 오탐이 본 목록을 더럽히면 신뢰를 잃는다.

## 7. 단계별 작업

### Phase 1 — 수동으로 돌아가는 상태 · 먼저 여기까지

```
1-1  reg_items 테이블 생성 · 빈 배열
1-2  reg-history.html 생성 · 사이드바 메뉴 추가
1-3  타임라인 목록 — 연도·분기 그룹 · 필터 · 검색
1-4  상세 패널
1-5  등록·수정 폼 — kb-sop.html 의 저장 로직 재사용
1-6  리포트 연결 — 파일 업로드 → kb_documents 저장 → report_doc_id
1-7  samples/ 의 예시 1건을 실제로 등록해서 끝까지 확인
```

**1-7이 Phase 1의 완료 기준이다.**

## 9. 주의

### 9-1. 새로 만들지 말 것

```
문서 저장 로직      kb-sop.html 것을 쓴다
문서 렌더러         iframe srcdoc 방식을 그대로 쓴다
권한 판정           rbac.js 를 쓴다
토스트 · 날짜 포맷   portal.js 의 showToast · formatDate 를 쓴다
사이드바            buildSidebar 에 항목만 추가한다
```

### 9-2. 외부 호출

```
서버에서 호출한다 · 브라우저에서 하면 CORS 로 막힌다
인증키는 환경변수로 둔다 · 코드와 JSON DB 에 넣지 않는다
타임아웃 10초 · 실패해도 포탈 기동에 영향이 없어야 한다
```

### 9-3. 법령 본문

국가법령정보센터 자료는 **출처를 표시**하고, 원문 링크를 함께 둔다. 본문을 통째로 복제해 두지 말고 **필요한 조문과 별표 파일만** 저장한다.

### 9-4. 사전예고는 확정이 아니다

사전예고안과 실제 공포 조문은 다를 수 있다. 상태를 `사전예고` 로 둔 건은 상세 화면에 그 경고를 띄운다.

> 사전예고안이다. 확정 공포 조문과 다를 수 있으므로 적용 전 확정본 대조가 필요하다.

## 11. 구현 메모 (2026-10-18 반영)

실제 구현은 아래 파일로 이루어져 있다. 지시서와 다른 결정은 굵게 표시했다.

| 구분 | 파일 | 비고 |
|---|---|---|
| 화면 | `reg-history.html` | 타임라인 · 상세 · 수집함 · 등록폼. 메뉴는 업무 › 규정 개정이력 |
| 테이블 | `reg_items` · `reg_inbox` · `reg_collect_runs` | `server/server.js` requiredTables. id 접두사는 서버 공통 규칙 `reg_` |
| 리포트 임베드 | `js/report-embed.js` · `scripts/publish_regulation.py` | 한 줄 `iframe srcdoc`, 높이 자동. **첨부는 기존 kb 업로드 저장소(`/api/kb/upload`) 재사용** |
| 수집 | `scripts/collect_reg_history.py` | **법령정보 API 대신 금감원·금융위 게시판 5곳(세칙 예고·확정, 감독규정 예고·고시, 보험업법·시행령·시행규칙 입법예고)을 직접 읽는다** (인증키 불필요). hwpx·hwp 본문/표 추출. 보험업법·시행령 확정 공포본은 미수집(법령정보 API 필요) |
| 리포트 생성 | `reports/make_reg_report.py` | docs/01 서식. 템플릿 CSS 재사용. 신구조문 대비표 자동 추출(머리글 · 세로배치 · 바이너리 표) |
| 적재 | `scripts/load_reg_history.py` | `source_key`(원문 URL) 멱등. kb_documents(규정·기준) + reg_items + 첨부 |
| 일일 동기화 | `scripts/sync_reg_history.py` | 서버가 매일 `REG_COLLECT_HOUR`(기본 06시) 와 [수집 실행] 버튼에서 호출. 데이터는 `server/data/reg_history/` |
| 법령 API 수집함 | `server/lib/regcollect.js` · `config/reg_sources.json` | `LAW_API_KEY` 있을 때만 동작. 수집함(reg_inbox)에만 넣는다 |

환경변수: `PYTHON_EXE`, `REG_COLLECT_HOUR`, `REG_COLLECT_ENABLED=0`, `REG_SYNC_ENABLED=0`, `REG_SYNC_DAYS`(기본 120), `REG_HISTORY_DIR`, `LAW_API_KEY`, `LAW_API_BASE`.

수동 전체 재적재
```
python scripts/sync_reg_history.py --base-url https://portal.kkuks.com --data-dir server/data/reg_history --since 2023-01-01 --author-name 자동수집
```
pdf 첨부는 받지 않는다(같은 내용의 사본). 원문 링크는 각 건의 출처에 있다.
