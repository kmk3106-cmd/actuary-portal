# 포탈 일일 자체점검 체계 (매일 새벽, 자동)

매일 새벽 Claude 세션이 자동으로 켜져서 포탈의 **모든 메뉴를 팀장·직원 두 역할로 열어 보고, 버튼을 눌러 보고,
모달 폼에 가상의 글을 넣어 저장까지** 해 본다. 오류가 나오면 원인을 찾아 고치고, 다시 점검해 통과하면 커밋·푸시한다.
실서버(portal.kkuks.com) 데이터는 절대 건드리지 않는다 — 점검은 샌드박스 서버 + 임시 DB 사본에서만 한다.

## 1. 구성

| 구분 | 내용 |
|---|---|
| 점검 스크립트 | `scripts/qa/qa_smoke.js` (Node + playwright-core). 메뉴 목록은 `js/portal.js` 의 NAV 에서 읽는다(규칙 11 — 메뉴가 늘면 자동으로 점검 대상) |
| 스케줄 | Claude 예약 작업 "일일 포탈 자체점검 (상주세션)", 매일 **02:52 KST** 에 저장소가 붙어 있는 상주 작업세션("일일 포탈 자체점검 · 상주 작업세션")을 깨워 실행 (서버 혼잡을 피해 03:00 보다 몇 분 앞당김). 새로 띄우는 세션은 저장소가 안 붙어 푸시를 못 했기에 2026-10-20 부터 상주 세션 방식 |
| 결과 | `tmp/qa_out/report.md` · `report.json` · `shots/` (세션 안에서만), 이력은 `docs/qa/QA_LOG.md` 에 한 줄씩 누적(커밋) |
| 수정 반영 | `[일일점검 YYYY-MM-DD]` 커밋 → `master` 푸시 → PC 자동 pull (`server/` 변경 시 node 재시작) |

## 2. 시간 규칙 (KST)

- **시작 02:52**, **08:30 까지 끝낸다** (푸시 포함). 08:15 이 지나면 새 수정에 착수하지 않고, 검증 끝난 것만 푸시하고 나머지는 QA_LOG 에 "미해결" 로 남긴다.
- **05:45 ~ 06:45 푸시 금지.** PC 가 06:00 에 법령 개정이력 동기화(`scripts/sync_reg_history.py`)를 돌리는데, 그 사이 `server/` 변경이 pull 되면 node 가 재시작되며 동기화가 끊긴다. 이 시간에 푸시할 것이 생기면 06:45 이후로 미룬다.

## 3. 점검 내용 (qa_smoke.js)

각 화면 × 역할(team_leader, employee)에 대해:

| 항목 | 결함 종류 |
|---|---|
| 페이지 로드 (1400px) + JS 예외 · console.error | `로드 실패` · `JS 예외` · `console.error` |
| 세션이 있는데 login.html 로 튕김 | `로그인 튕김` |
| 같은 서버 요청의 4xx/5xx 응답 | `HTTP 오류 응답` |
| 본문에 `undefined` · `NaN` · `[object Object]` 노출 | `값 노출` |
| 사이드바 메뉴 미표시 | `사이드바 없음` |
| 1400px · 390px 가로 스크롤 | `가로 스크롤` |
| (팀장) 화면의 버튼·탭 전부 클릭 (삭제·로그아웃·초기화·발송·수집 실행 제외, 화면당 최대 40개) | `클릭 오류` |
| (팀장) 열린 모달의 빈 입력란을 채워 저장 → 실패 토스트/예외 | `저장 실패 토스트` · `저장 중 오류` |
| 서버 콘솔의 스택 트레이스 | `서버 로그 오류` |

환경 탓(외부 CDN 차단, 파이썬 모듈 없음, 버튼이 페이지를 새로고침)은 결함으로 세지 않고 "환경 메모" 로만 적는다.
종료코드 0 = 결함 없음, 1 = 결함 있음, 2 = 스크립트 자체 실패.

수동 실행:
```
npm i --prefix tmp playwright-core        # 최초 1회
pip install openpyxl                      # 월결산 엑셀 생성(/weekly/closing) 점검용
node scripts/qa/qa_smoke.js --out tmp/qa_out
node scripts/qa/qa_smoke.js --pages settlement.html,kb-sop.html --roles team_leader --no-forms   # 일부만
```
옵션: `--port`(기본 8930) `--seed <db.json>`(실데이터 사본으로 점검) `--max-clicks` `--keep-db`.
클라우드 샌드박스에서는 `HTTPS_PROXY` 가 있으면 브라우저가 그 프록시로 CDN 을 받는다(샌드박스 자신은 직접 접속).

## 4. 자동 세션의 수정 원칙

1. 결함마다 원인을 찾아 코드를 고친다. **점검 스크립트를 느슨하게 하거나, 테스트를 끄거나, 결함을 환경 메모로 돌려 숨기지 않는다.**
2. 고친 뒤 `qa_smoke.js` 를 다시 돌려 그 결함이 사라졌는지 확인하고, 관련 E2E(`tmp/_check_*.js` 가 있으면)도 돌린다 (규칙 18).
3. 다음은 고치지 않고 QA_LOG 에 "검토 필요" 로 남긴다: 데이터 모델·동기화 흐름 변경(규칙 13), 삭제·초기화 로직, 기능 의미가 바뀌는 설계 변경, 외부 연동(텔레그램·법령 수집) 자격 증명.
4. CLAUDE.md 규칙을 지킨다 — 특히 규칙 14(main.css SSOT, 고치면 `?v=` +1), 규칙 11(설정 SSOT), 규칙 9(루프 추적), 규칙 2(하드코딩 금지).
5. 커밋 메시지 `[일일점검 YYYY-MM-DD] 무엇을 왜` + 세션의 attribution 규칙. 코드·커밋에 모델 식별자를 넣지 않는다.
6. 수정이 없어도 `docs/qa/QA_LOG.md` 한 줄은 커밋한다 (점검이 돌았다는 증거).

## 5. QA_LOG 형식

```
| 2026-10-19 | 화면 54 | 결함 3 → 0 | kb-sop 카테고리 onclick 따옴표 누락 수정 · settlement 가로 스크롤 수정 | 미해결: 없음 |
```

## 6. 예약 작업 바꾸기

Claude 앱의 예약 작업 목록에서 "일일 포탈 자체점검" 을 끄거나 시간을 바꾼다. 점검 범위를 바꾸려면 `scripts/qa/qa_smoke.js` 의
`DANGER_RE`(누르지 않는 버튼) · `IGNORE_REQ_RE`(무시할 요청) · `WIDTHS` 를 고친다.
